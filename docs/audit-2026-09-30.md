# Service and endpoint audit — 2026-09-30

Repaired copied upstream hostnames: these resources are provided by ESPN, not `site.api.nfl.com` or other invented NFL hosts. Renamed the ignored lowercase Django setting to `NFL_CLIENT`. Ported the tested ESPN endpoint expansion and inclusive daily-fetch date-range workaround (at most 31 days). Terminal 4xx and malformed JSON are not retried. Ingestion triggers require staff access. Existing environment variable names remain accepted; custom Django settings modules must use `NFL_CLIENT`.

## Runtime and packaging

The service now requires Django `>=5.2.17,<5.3` (the 5.2 LTS series) and Django REST Framework 3.16 or later. Where used, django-filter now permits its Django 5.2-compatible 25.x series. Django's removed `STATICFILES_STORAGE` setting is replaced by `STORAGES`. Deployment must reinstall dependencies/rebuild images to receive these changes; this audit did not deploy services or change production databases.

References: [Django supported versions](https://www.djangoproject.com/download/) and [5.2.17 security release](https://www.djangoproject.com/weblog/2026/aug/04/security-releases/).

## Verification

The service-validation workflow runs Django system checks, migration-drift checks, migrations, tests against PostgreSQL 16 on Python 3.12/3.13, package builds, and Docker builds. Local tests use isolated SQLite unless `TEST_DATABASE_URL` is explicitly supplied. Production `DATABASE_URL` is not reused as the test database.

Live probe results, timestamps, HTTP statuses, and top-level response keys are recorded in [the endpoint evidence](data/endpoint-probes-2026-09-30.json). A successful request is evidence for that sample only. A 403, timeout, or unavailable sample is not labeled verified. Private Fantasy league ingestion was not exercised without credentials. Upstream APIs are undocumented and can change independently of this repository.

These changes cover the concrete defects and additions identified in this pass; they do not assert an exhaustive inventory of every upstream route.

## Ingestion migration

Ported the ESPN ingestion safeguards: savepoints isolate bad records, injuries validate the whole snapshot before replacement, athlete stats respect the requested season, and transaction refreshes have stable identities. Migration `0003_transaction_identity` consolidates duplicate transactions, retaining the most recently updated row for each identity, before adding the unique constraint. Back up an existing database before deployment: deleted duplicate rows cannot be restored by reversing the migration. No production database was migrated during this audit.
